# گزارش اجرای اتصال ۷۲ رکورد کاتالوگ وب ARIA به قراردادهای ۶۳۹‌گانه

تاریخ: ۲۰۲۶-۱۱-۱۹
وضعیت: پیاده‌سازی در شاخه مهندسی؛ ادغام و انتشار نشده

## نتیجه قابل اثبات در مخزن
- ۷۲ رکورد موجود در کاتالوگ وب از `server.js` استخراج و با دامنه مرجع `MODULE_DOMAIN_BY_ID` تطبیق داده شده‌اند.
- فایل مرجع `backend/data/aria_web_catalog_bridge.json` شامل ۷۲ رکورد، mapping، مدل درآمد، وضعیت کاتالوگ، شناسه قرارداد و مشخصات وابستگی بیرونی است.
- شناسه‌های قرارداد افزایشی ۶۵۱ تا ۷۲۲ رزرو شده‌اند؛ جمع هدف ۷۱۱ = ۶۳۹ قدیمی + ۷۲ وب.
- برای موارد دارای هم‌پوشانی، `aliasOfModuleId` به قرارداد قدیمی اشاره می‌کند تا قابلیت مشترک تکراری نشود؛ رکوردهای مبنا حذف نمی‌شوند.
- هفت حوزه‌ای که پیش‌تر با نام محصولات مستقل معرفی شده بودند، در کاتالوگ عمومی به نام‌های حوزه‌ای ARIA تغییر کرده‌اند؛ شناسه‌ها و قابلیت‌های یکتا حفظ شده و برچسب محصول قدیمی از خروجی عمومی حذف شده است.
- API وب هر ۷۲ رکورد را با `capabilityContractId` عرضه می‌کند و endpoint برنامه‌ریزی محلی `POST /api/modules/:contractId/plan` اضافه شده است.
- وضعیت `ACTIVE_LOCAL_WORKFLOW` فقط تولید برنامه/گردش‌کار محلی ساختاریافته را بیان می‌کند. انتشار شبکه اجتماعی، رندر رسانه، پرداخت، رزرو، تراکنش، یا تغییر سرویس بیرونی اجرا نشده و تا اتصال adapter رسمی، مجوز و آزمون جداگانه مسدود است.
- اسکریپت overlay برای افزودن ۷۲ قرارداد به سه رجیستری Android/backend/capabilities و حفظ digest شناسه‌های ۶۳۹‌گانه ایجاد شده است. اصلاح شد تا تمام assertهای تکرارشونده تعداد ۶۳۹ در گیت ماتریس به ۷۱۱ ارتقا یابند. اجرای آن روی candidate باید در workflow اندروید انجام و با گیت‌ها اثبات شود.
