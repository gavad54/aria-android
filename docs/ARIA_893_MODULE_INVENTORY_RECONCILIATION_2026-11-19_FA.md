# ممیزی و تطبیق موجودی ۸۹۳ واحد ماژولی ARIA
تاریخ: 2026-11-19
شاخه: `engineering/aria-preserve-all-capabilities-2026-11-19`
وضعیت: موجودی سلسله‌مراتبی در API ثبت شده؛ CI وب/API باید برای آخرین commit تأیید شود؛ Production تأیید نشده است.

## عدد مرجع و قاعده شمارش

عدد ۸۹۳ از چهار مجموعه با شناسه و نوع مجزا ساخته می‌شود:

| لایه | تعداد | معنی |
|---|---:|---|
| ماژول‌های canonical | ۶۳۹ | قراردادهای پایه و immutable |
| overlay تاریخی ماژولی | ۱۱۱ | ۵۰ مسئله تاریخی + ۵۰ ایده + ۴ کنترل + ۷ دامنه تاریخی |
| ماژول‌های کاتالوگ تجاری | ۷۲ | شناسه‌های مستقل کاتالوگ تجاری در بازه ۶۵۱ تا ۷۲۲ |
| زیرماژول‌های موتور | ۷۱ | شناسه‌های مستقل برای موتورهای تخصصی متصل به ماژول‌های دامنه‌ای |
| **مجموع موجودی سلسله‌مراتبی** | **۸۹۳** | ماژول‌ها و زیرماژول‌های ثبت‌شده در چهار لایه |

فرمول: ۶۳۹ + ۱۱۱ + ۷۲ + ۷۱ = ۸۹۳.

## تمایز مهم برای گزارش درست

۸۹۳، تعداد رکوردهای ماژول/زیرماژول در موجودی سلسله‌مراتبی است؛ به معنی ۸۹۳ قرارداد اجرایی مستقل، ۸۹۳ قابلیت E2E آزموده‌شده یا ۸۹۳ قابلیت Production نیست.

- ۱۱۱ رکورد overlay تاریخی شامل ۳۶ شناسه منتقل‌شده به محصولات خواهر و ۳ دامنه بایگانی‌شده است؛ این موارد در lineage حفظ می‌شوند، اما نباید به‌عنوان ماژول فعال متعلق به ARIA نمایش داده شوند.
- از ۱۱۱ رکورد تاریخی، ۷۲ رکورد در کاتالوگ عمومی فعلی ARIA باقی می‌مانند.
- ۷۲ ماژول تجاری دارای شناسه کاتالوگ جدا هستند، اما به ۴۷ قرارداد canonical یکتا نگاشت شده‌اند. چند offer می‌توانند از یک قرارداد میزبان استفاده کنند؛ این به‌تنهایی اثبات تکراری‌بودن قابلیت نیست.
- ۷۱ موتور زیرماژول‌اند، نه ۷۱ قابلیت موازی و مستقل از والد. هر موتور شناسه مستقل دارد و باید به یک یا چند ماژول والد متصل باشد.
- مسئله تاریخی شماره ۴۸ با شماره ۲۹ موتور مشترک دارد؛ دو ورودی/مسیر دامنه‌ای حفظ می‌شوند، اما موتور تکراری ساخته نمی‌شود.
- هیچ شناسه پایه، منبع تاریخی یا قابلیت موجود حذف یا بازشماری نشده است.

## تغییرات فنی ثبت‌شده

1. رجیستری تجاری ۷۲تایی به runtime متصل شد.
2. ۷۱ موتور با شناسه‌های `ARIA-ENGINE-MODULE-001..071` به‌صورت زیرماژول قابل‌ردیابی در API موجودی ثبت شدند.
3. برای هر زیرماژول موتور، `engineId` و `parentModuleIds` ثبت می‌شود.
4. runtime در صورت نبود والد یا شناسه والد نامعتبر fail-fast می‌کند.
5. endpoint جدید `GET /api/aria-expansion/inventory` چهار لایه موجودی را همراه با روابط و وضعیت‌ها ارائه می‌کند.
6. endpointهای summary، capability-matrix و engines شمارنده و breakdown جدید را ارائه می‌کنند.
7. رابط وب عدد ۸۹۳ را همراه با تفکیک لایه‌ها نمایش می‌دهد و صریحاً اعلام می‌کند که این عدد معادل ۸۹۳ اجرای Production نیست.
8. تست‌های قراردادی برای جمع ۸۹۳، یکتایی شناسه‌های ۷۲ و ۷۱ و اتصال تمام ۷۱ موتور به ماژول والد اضافه شده‌اند.

## وضعیت واقعی قابلیت‌ها

- کاتالوگ ۷۲تایی: شناسه، شرح، مدل درآمدی، نگاشت canonical و وضعیت تجاری دارد. بعضی مسیرها فقط برنامه‌ریزی محلی/نمونه هستند؛ این به معنی اجرای کامل عملیات دامنه نیست.
- موتورهای ۷۱گانه: شناسه و قرارداد و ارتباط والد در رجیستری دارند؛ وضعیت عملیاتی مستقل آن‌ها تا زمان تست واحد، integration و E2E اثبات نشده است.
- پرداخت و درآمد زنده: غیرفعال.
- اتصال providerهای بیرونی: تا زمان پیکربندی رسمی، رضایت، sandbox و آزمون، غیرفعال.
- انتشار Production: تأیید نشده.

## گیت‌های تکمیل واقعی مراحل ۳ تا ۶

برای هر یک از ۷۲ ماژول تجاری باید به‌ترتیب تکمیل شود: handler دامنه‌ای اختصاصی، schema ورودی/خروجی نسخه‌دار، persistence و migration، tenant authorization، quota/entitlement، ثبت audit، خطا و retry، unit/contract/integration/E2E، telemetry و rollback.

برای هر یک از ۷۱ موتور باید قرارداد اجرا، ورودی/خروجی، میزبان، وابستگی، سیاست دسترسی، بودجه/سهمیه، تست مستقل و evidence به commit/CI ثبت شود. اتصال رجیستری به والد به‌تنهایی اثبات اجرای موتور نیست.

## اصل ضدادغام اشتباه

- تنها مواردی ادغام می‌شوند که هم‌پوشانی معنایی، ورودی/خروجی، داده، نتیجه و مسئولیت دامنه‌ای آن‌ها اثبات شود.
- مواردی که فقط از یک قرارداد canonical یا موتور مشترک استفاده می‌کنند، حذف یا یکی نمی‌شوند؛ رابطه والد/فرزند، alias یا shared-engine ثبت می‌شود.
- هر ادغام باید lineage، شناسه قدیمی، شناسه مقصد، دلیل، آزمون عدم رگرسیون و مسیر بازگشت داشته باشد.
